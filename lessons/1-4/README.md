# 1-4 NULLの扱い

1-3 の Q2 で、誕生日が「わからない」人に `null` を入れた。
NULL は「0」でも「空っぽの文字」でもなく、**「値がわからない・ない」** という特別な印。

ふつうの値と同じ感覚で扱うと、思わぬところで行が消えたり、計算結果が消えたりする。
今回はそのクセを、予想 → 実行 で体験する。

使うのは `users`(会員)。最初のデータでは、田中 健さんと中村 翔太さんの誕生日が NULL になっている。

## 問題

答えは `answer.sql` の各 `-- Q` の下に書く。書けたら `./sql lessons/1-4/answer.sql` で実行して確かめる。
(今回はデータを変えないので、何回流しても大丈夫)

**Q1(予想してから実行する問題).** 誕生日が登録されていない会員を探したくて、こう書いた。

```sql
select name, birthday from users where birthday = null;
```

何件出ると思う? 予想を書いてから実行する。

**Q2.** Q1 の結果をふまえて、誕生日が登録されていない会員を **正しく** 探す SQL を書く。
(ヒント: NULL かどうかを確かめるには、`=` ではなく専用の書き方がある。「〜は NULL である」を英語で言うと?)

**Q3.** 反対に、誕生日が **登録されている** 会員だけを出す。

**Q4(予想してから実行する問題).** 「佐藤 花子さん(誕生日 1995-03-14)と誕生日が違う人」を出したくて、こう書いた。

```sql
select name, birthday from users where birthday <> '1995-03-14';
```

会員は全部で12人。何件出ると思う? 予想を書いてから実行する。
予想と違ったら、出てこなかったのは誰か、なぜかを考える。

**Q5.** Q4 を直して、「誕生日が 1995-03-14 ではない人」を **誕生日がわからない人も含めて** 全員出す。

**Q6(予想してから実行する問題).** 次の SQL を実行すると、`a`・`b`・`c` はそれぞれ何になると思う?

```sql
select null + 1 as a, 'abc' || null as b, null = null as c;
```

(`||` は文字列をつなげる記号。`'abc' || 'def'` は `'abcdef'` になる)

**Q7.** 会員を誕生日の古い順(`order by birthday`)に並べる。
- まず、誕生日が NULL の2人は **一番上と一番下のどちらに来るか** 予想してから実行する
- そのあと、NULL の人が **一番上** に来るように書き換える
(ヒント: `order by birthday nulls ...`)

**Q8.** 名前と誕生日を出すとき、誕生日が NULL の人は `未登録` と表示したい。
`coalesce(A, B)` は「A が NULL でなければ A、NULL なら B」を返す関数。これを使って書く。
(ヒント: birthday は日付型なので、文字の `'未登録'` とは混ぜられない。`birthday::text` と書くと文字に変えられる)

**Q9(書かずに考える問題).** もし `products.stock`(在庫)に NULL を入れてよいことにして、
「在庫の数がまだ数えられていない商品」を NULL にしたとする。

- 在庫が `0` の商品と、在庫が `NULL` の商品は、意味がどう違う?
- 「在庫切れの商品一覧」を `where stock = 0` で出したとき、在庫が NULL の商品は出てくる? それは困る? 困らない?

`answer.sql` にコメントで考えを書いておいて。
